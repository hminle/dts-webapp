An MCP server for the Treasury data

An AI assistant gets five tools for asking the app's data questions directly. It runs on your machine first and is built so it can go public later.

The idea in one picture

Custom queries are fenced in

A query can only read the database. It can't change anything, open other files, or reach the internet. It stops after 10 seconds and returns at most 2,000 rows.

guide text+ numbers from the code

The guides can't go stale

The guides don't hold hand-copied facts. Table layouts, category line items and example numbers are filled in from the app's own code each time a guide is read.

your laptop→ later: the public site

Local first, public later

First it runs on your machine for Claude Code. Every limit is already set for public use, so going public only means turning it on in the live app.

Part 2

Developer briefing

Goal

Add backend/app/mcp_server/, a FastMCP 4 server (fastmcp>=4.1.3,<5) with five generic tools over the existing FastAPI app and the read-only DuckDB artifact. It runs over stdio from .mcp.json (uv run python -m app.mcp_server). Phase 4 can later mount the same server as stateless streamable HTTP at /api/mcp/. No new FastAPI routes, so docs/contracts/openapi.json never changes.

One run_query call

Key decisions

  • The lockdown goes on the one shared connection. DuckDB 1.5.6 refuses a second connection to the same file with a different config, so get_connection() itself runs SET enable_external_access = false and then SET lock_configuration = true. Both are set after connect, because passing them in config makes DuckDB reject temp_directory.
  • Only a single SELECT. DESCRIBE, SHOW, SUMMARIZE, FROM t and VALUES parse as SELECT and are allowed. PIVOT parses as CREATE + SELECT and gets its own message.
  • Limits fail loudly. Hitting the row cap sets truncated: true. A timeout, the byte cap or busy slots raise ToolError with a way to narrow the query.
  • Skills render from code. The schema comes from information_schema, categories from CATEGORY_REGISTRY, and numbers from app/mcp_server/worked-examples.json, a copy that a test keeps byte-equal to the frontend file. Every ```sql block in a skill runs in CI.
  • No circular import. build_server(api) takes the FastAPI app as an argument. The stdio entrypoint and app/main.py both call it, and app/mcp_server never imports app.main.
  • Public mode has no auth. The data is public domain. The query limits and the existing api-per-ip WAF rule (300 per minute on /api/) handle abuse.

Risks

The lockdown breaks DuckDB spilling to /tmp/duckdb
Phase 1 runs a manual check with APP_DUCKDB_MEMORY_LIMIT=50MB. If spilling is off, the memory limit still protects the process.
FastAPI ignores unknown query params, so a typo returns unfiltered data
call_api checks every param name against the spec first.
A mount at /api/mcp redirects requests without the trailing slash (307)
Docs use /api/mcp/. A test records the behaviour, and no second route is added to hide it.
Skill facts drift from the app
Placeholders fill facts in from the code. The worked-examples copy is checked byte for byte, and every SQL block runs in tests.
A cross join ties up the function
A 10 s interrupt, 2 query slots, a 1 GB memory limit and the WAF rate limit.
